### 2.2 文件之间的关系

| 文件类型 | 用途 | 初学时的记忆方法 |
|---|---|---|
| `.qpf` | 工程文件 | 整个实验的入口 |
| `.qsf` | 工程设置 | 保存器件、顶层等配置 |
| `.bdf` | 原理图 | 电路本身 |

| `.vwf` | 波形文件 | 既可能是输入激励，也可能是导出的实际结果，要看来源和文件名 |
| `.rpt` | 报告 | 编译、仿真过程和诊断信息 |

**工程名与顶层名可以不同。** 本次工程叫 `COExp`，测试触发器时顶层是 `test_dff`，测试寄存器堆时应切换为 `GPRs`。

### 2.3 Node 与 Bus

- `Clk`、`Wr` 各只有 1 位，是单根信号线 Node。
- `DIn[31..0]` 是 32 位总线 Bus。
- `rA[4..0]` 是 5 位地址总线。
- 在原理图中使用 `[31..0]` 这样的双点写法，不要直接写成 Verilog 的 `[31:0]`。
- 同一张原理图中，名称相同的网络可以实现连接，不必拉长线横跨整个图。
- `wire` 可用于网络重命名，本身不增加逻辑运算；本次简单的 DFF 测试图使用了直接连接。

## 4. 制作 32 位带使能 D 触发器

### 4.1 建立原理图

1. 选择 **File → New**。
2. 在 **Device Design Files** 中选 **Block Diagram/Schematic File**。
3. 点 OK，进入带网格的原理图编辑区。
4. 用 **File → Save As** 保存为 `D:\COExp\test_dff.bdf`。
5. 如果对话框提供 **Add file to current project**，勾选它。

### 4.2 使用 MegaWizard 生成 `lpm_dff0`

1. 双击原理图空白处，或点击 **Symbol Tool**。
2. 在符号选择窗口的 Name 中输入 `lpm_dff`。
3. 通过向导创建参数化模块；本次界面出现 **Launch MegaWizard Plug-In Manager** 选项时使用该选项继续。
4. 输出目录选工程目录 `D:\COExp`。
5. 模块名采用 **`lpm_dff0`**，末尾是数字 0。
6. 本次选择 **AHDL** 输出，因此生成 `.tdf`。
7. 数据宽度设为 **32**。
8. 启用 **clock enable / enable** 输入。
9. 不增加异步清零、同步清零、置位等本实验接口没有要求的端口。
10. 生成符号文件，完成向导。

正确的模块接口应当是：

| 端口 | 位数 | 方向 | 含义 |
|---|---:|---|---|
| `data[31..0]` | 32 | 输入 | 待写入数据 |
| `clock` | 1 | 输入 | 时钟，上升沿触发 |
| `enable` | 1 | 输入 | 写入使能 |
| `q[31..0]` | 32 | 输出 | 已保存的数据 |

以后再放置同样的模块，应从 **Symbol Tool → Project** 中选择已有 `lpm_dff0`。不要每放一个寄存器就重新创建一个不同名字的模块。

### 4.3 生成引脚并改名

本次使用了较快的方法：

1. 将 `lpm_dff0` 放到原理图空白处。
2. 选中模块，右键选择 **Generate Pins for Symbol Ports**。
3. Quartus 自动生成输入/输出引脚及对应连接。
4. 双击引脚，修改名称；有 Properties 菜单时也可通过属性窗口修改。
5. 按下表核对每个引脚真正连到哪个端口。

| 原理图外部引脚 | 所连接的模块端口 |
|---|---|
| `DIn[31..0]` | `data[31..0]` |
| `Clk` | `clock` |
| `Wr` | `enable` |
| `DOut[31..0]` | `q[31..0]` |

如果手工画线，数据端使用 Bus，时钟和使能使用 Node。连线应接到引脚端点；只看起来碰到模块边框不代表连接成功。

完成后按 **Ctrl+S** 保存。正常逻辑为：

```text
在 Clk 上升沿：
    Wr = 1  → DOut 更新为 DIn
    Wr = 0  → DOut 保持原值

没有 Clk 上升沿：
    DOut 保持原值
```

`enable` 不是另一根时钟。不要为了实现使能自行把 `Wr` 与 `Clk` 做与运算；这里直接使用模块提供的 enable 端口。

## 6. 创建触发器输入波形

### 6.1 建立 VWF 并插入信号

1. 选择 **File → New → Other Files → Vector Waveform File**。
2. 保存为 `D:\COExp\test_dff_checks.vwf`。
3. 在波形编辑器左侧 **Name** 区域右键。
4. 选择 **Insert → Insert Node or Bus**。
5. 点 **Node Finder**。
6. Filter 设为 **Pins: all**，点 **List**。
7. 加入 `Clk`、`Wr`、`DIn[31..0]`、`DOut[31..0]`，确认返回。

如果找不到信号，先检查是否已经成功编译、顶层是否为 `test_dff`。列表可能同时列出总线和各个位，最终波形按四组信号查看即可，不需要重复添加同一信号。

### 6.2 显示格式与时间长度

1. 在 Name 区域选中 `DIn`、`DOut` 总线。
2. 通过右键 **Properties** 将显示进制设为 **Hexadecimal**。
3. 将仿真结束时间设为 **100 ns**，在本版本波形编辑器的 **Edit → End Time** 中设置。
4. 若要手工拖选 35 ns、55 ns 等边界，可把网格设置为 **5 ns**，或使用选择区间的精确时间输入。

折叠总线在波形窗口可能只显示 `DIn`、`DOut`，不带范围，这是正常的。32 位数据用 8 位十六进制数字表示。

### 6.3 时钟 `Clk`

选择 Clk 的整个 0–100 ns 区间，使用工具栏的 **Clock** 功能设置：

- 周期：20 ns。
- 占空比：50%。
- 0–10 ns 为低电平。
- 10–20 ns 为高电平，之后重复。

设置后直接看波形确认，上升沿必须位于 **10、30、50、70、90 ns**。不同对话框的偏移参数容易混淆，以实际边沿位置为准。

### 6.4 写使能 `Wr`

所有时间区间均为左闭右开，例如 `[35,55)` 表示 35 ns 起变为 0，55 ns 起恢复为 1。

| 时间区间 / ns | Wr |
|---|---:|
| 0–35 | 1 |
| 35–55 | 0 |
| 55–100 | 1 |

手工设置时，拖选对应区间，点击工具栏的置 0 或置 1 按钮。不要误设置成 30–50 ns，否则就不是本次同一组测试。

### 6.5 输入数据 `DIn`

| 时间区间 / ns | DIn，十六进制 |
|---|---|
| 0–20 | `11111111` |
| 20–40 | `22222222` |
| 40–60 | `33333333` |
| 60–80 | `FFFFFFFF` |
| 80–100 | `80000001` |

选择总线的时间区间，双击相应区间输入值；必要时使用右键的赋值命令。确认进制为 Hexadecimal 后输入上述数字，不要逐位设置 32 条线。

`DOut` 是电路输出，输入激励文件中保持 X 即可。**不要把预期答案填入 DOut 后截图冒充真实仿真。** 本次准备的激励文件中，输出通道全为 X。

完成后保存。已有 `test_dff_checks.vwf` 时可以直接打开查看，无须重新逐段制作。

## 8. 分析本次触发器的实际结果

### 8.1 关键事件与真实输出

| 时刻 / ns | 事件 | 实际 DOut，十六进制 | 说明 |
|---:|---|---|---|
| 10 | 上升沿，Wr=1 | `11111111` | 写入当前 DIn |
| 20 | DIn 改变，时钟下降沿 | 保持 `11111111` | 下降沿不写入 |
| 30 | 上升沿，Wr=1 | `22222222` | 正常写入 |
| 35 | Wr 变为 0 | 保持 `22222222` | 关闭写入 |
| 40 | DIn 改为 `33333333` | 保持 `22222222` | 输入改变不立即写入 |
| 50 | 上升沿，Wr=0 | 保持 `22222222` | 验证禁写有效 |
| 55 | Wr 恢复为 1，Clk 已处于高电平 | 保持 `22222222` | 仅恢复使能不触发写入 |
| 60 | DIn 改为 `FFFFFFFF`，下降沿 | 保持 `22222222` | 等待下一上升沿 |
| 70 | 上升沿，Wr=1 | `FFFFFFFF` | 正常写入 |
| 80 | DIn 改为 `80000001`，下降沿 | 保持 `FFFFFFFF` | 再次验证保持 |

## 9. 构建 32×32 位寄存器堆

**本节描述设计与后续操作。当前原理图仍须 Quartus 编译和实际功能仿真确认。**

### 9.1 功能与接口

寄存器堆逻辑上有 32 个 32 位寄存器，编号 0–31。0 号寄存器恒为零，因此实际只需要 31 个可写的 32 位寄存器，即 992 个存储位。

| 外部信号 | 位数 | 方向 | 含义 |
|---|---:|---|---|
| `Clk` | 1 | 输入 | 写操作时钟 |
| `Wr` | 1 | 输入 | 写使能 |
| `rW[4..0]` | 5 | 输入 | 写地址 |
| `dW[31..0]` | 32 | 输入 | 写数据 |
| `rA[4..0]` | 5 | 输入 | A 端口读地址 |
| `rB[4..0]` | 5 | 输入 | B 端口读地址 |
| `dA[31..0]` | 32 | 输出 | A 端口读数据 |
| `dB[31..0]` | 32 | 输出 | B 端口读数据 |

两个读端口是组合逻辑：地址改变后就应读到相应数据，不必等下一次时钟上升沿。写端口在上升沿且 Wr=1 时更新非零地址寄存器。

```text
写操作：上升沿且 Wr=1 且 rW≠0 时，R[rW] ← dW
读操作：dA = R[rA]，dB = R[rB]
固定约束：R[0] = 00000000
```

### 9.2 电路组成

| 部件 | 数量 | 参数/用途 |
|---|---:|---|
| 32 位带使能 DFF | 31 | 共用 `lpm_dff0` 模块定义，存储 R1–R31 |
| 5→32 译码器 | 1 | 把写地址译成各寄存器写使能 |
| 32 选 1、每路 32 位的多路选择器 | 2 | 分别生成 dA、dB |
| 32 位零信号 | 1 组 | 提供 R0，送入两个读选择器的第 0 路 |

### 9.3 课程向导方式的参数

如果从零手工搭建，按课程要求使用 `lpm_dff`、`lpm_decode`、`lpm_mux` 生成模块，再从当前工程的 Project 符号库放置。

译码器：

- `LPM_WIDTH = 5`。
- `LPM_DECODES = 32`。
- `LPM_PIPELINE = 0`，采用组合译码。
- 数据输入接 `rW[4..0]`。
- enable 接 `Wr`。
- 输出命名为 `WEn[31..0]`。

读选择器：

- `LPM_WIDTH = 32`：每一路数据为 32 位。
- `LPM_SIZE = 32`：共 32 路输入。
- `LPM_WIDTHS = 5`：选择地址为 5 位。
- `LPM_PIPELINE = 0`：不增加时钟流水级，保持异步读。
- 两个实例可以使用同一个模块定义，分别接 `rA`、`rB`。

不要把“32 路输入”和“每路 32 位”混为一个参数，也不要启用读选择器的寄存输出。

### 9.4 连线检查

对每个寄存器 `i=1…31`：

```text
lpm_dff0.data   ← dW[31..0]
lpm_dff0.clock  ← Clk
lpm_dff0.enable ← WEn[i]
lpm_dff0.q     → R[i][31..0]
```

读通路：

- `R[0][31..0]` 接零。
- `R[1][31..0]` 到 `R[31][31..0]` 接各寄存器输出。
- 两个选择器接收相同的 32 路数据。
- A 选择器的 sel 接 rA，result 接 dA。
- B 选择器的 sel 接 rB，result 接 dB。
- `WEn[0]` 不连接到可写寄存器，保证对 0 地址的写操作无效。

当前生成图采用二维网络名称 `R[31..0][31..0]` 汇集 32 路、每路 32 位的数据。每个 `R[i][31..0]` 必须映射到相同编号的读选择器输入。

### 9.5 当前 `GPRs.bdf` 的来源与实现方式

课程文字提到可提供 `GPRs.bdf`，但本次没有在用户给出的附件中取得原始电路文件。因此，目前文件是依据功能要求重新构建的原理图。

当前图里，31 个寄存器使用已由向导生成的 `lpm_dff0`；译码器和两个选择器使用 Quartus 原生的参数化 `LPM_DECODE`、`LPM_MUX` 符号，并在符号中设置参数。它们不是已经通过本次向导另外生成的 `lpm_decode0`、`lpm_mux0` 包装文件。

### 10.2 第一阶段：0–640 ns，依次写入所有地址

|---|---|---|
| `00` | `A5A50000` | `00000000`，零号不可改写 |

| `1F` | `A5A5001F` | `A5A5001F` |

### 10.3 第二阶段：640–1285 ns，禁止写入并遍历两个读口

640–645 ns 的过渡段：

```text
Wr=0，rW=01，dW=DEADBEEF，rA=1F，rB=00
```

645 ns 起，每 20 ns 更换一次读地址。对于 `k=0…31`：

```text
区间：[645+20k,665+20k) ns
rA=k，rB=31-k
Wr=0，rW=01，dW=DEADBEEF
```

两路应分别读出对应寄存器原来的数据；读地址为 0 时输出零。虽然仍有时钟上升沿，但 Wr=0，R1 不得变成 `DEADBEEF`。

读地址切换发生在下一上升沿前 5 ns。检查地址切换后、上升沿前的结果，才能验证“异步读取”，避免只在上升沿之后观察而漏掉错误的同步读电路。

### 10.4 第三阶段：边界情况与覆盖写入

下表的地址均为十六进制，所有输出都是预期值。

| 区间 / ns | Wr | rA | rB | rW | dW | 预期行为 |
|---|---:|---|---|---|---|---|
| 1285–1305 | 1 | 00 | 01 | 00 | FFFFFFFF | 1290 ns 尝试写 R0；dA 仍为 0，dB 为 A5A50001 |
| 1305–1325 | 0 | 01 | 1F | 01 | DEADBEEF | 1310 ns 禁写；dA 为 A5A50001，dB 为 A5A5001F |
| 1325–1345 | 1 | 01 | 1F | 1F | 80000001 | 1330 ns 写 R31；dB 变为 80000001，dA 不变 |
| 1345–1365 | 1 | 01 | 1F | 01 | FFFFFFFF | 1350 ns 写 R1；dA 变为 FFFFFFFF，dB 不变 |

这组激励覆盖全部地址的读写、双读口、零号寄存器、禁写保持、上升沿写入及读地址交换。辅助核验器准备了 **214 个输出检查项**；只有真实输出与全部期望匹配后，才能说 214/214 通过。

## 13. 常见问题排查

### 13.1 点不了编译或提示没有工程

先 File → Open Project 打开 `.qpf`。只打开 `.bdf` 不等于已打开它所属的工程。

### 13.2 找不到 `lpm_dff0` 或提示 undefined entity

检查 `.tdf` 与 `.bsf` 是否都在工程目录，模块名是否准确，末尾是否为数字 0。`.bsf` 存在只代表有符号，不代表定义文件已找到。必要时把 `lpm_dff0.tdf` 通过工程文件列表显式加入，再编译。

本次虽然已经加入了 `.qip`，编译仍提示自动发现 `lpm_dff0.tdf`；因此应按实际消息确认，不要以为有 `.qip` 就绝不会出现文件归属提示。

### 13.3 总线宽度不匹配、地址或数据接反

数据为 32 位、地址为 5 位、使能为 1 位。检查是否误用了单线、写成 `[32..0]`、接到错误端口，或给本应不同的网络起了相同名称。32 位范围是 `[31..0]`。

### 13.4 DOut 一直是 X

先确认正在看 **Simulation Report** 或 `test_dff_result.vwf`，而不是输入激励。再检查时钟是否出现上升沿、Wr 是否为 1、模块及网络是否连接、网表是否对应最新设计。

### 13.5 输入改变后输出立刻改变

先看观察的是输入还是输出。若确实 DFF 输出无上升沿就跟随输入，检查是否绕过了 DFF、误接同名网络，或者测试的顶层并非所需电路。

### 13.6 波形时间或数值看起来不对

确认单位：`100 ns = 100000 ps`，`1400 ns = 1.4 μs`。总线进制选 Hexadecimal，避免 ASCII。5 位地址最大为 `1F`，不是十六进制 `31`。

### 13.7 改了原理图，但仿真还是旧输出

按顺序执行：保存 → 设置正确顶层 → 重新编译 → 重新生成功能网表 → 选择匹配的输入 VWF → 仿真。只重新点 Start 不一定会更新旧网表。

### 13.8 仿真运行成功，能否直接宣布电路正确

不能。成功提示只说明仿真器完成运行。还要比较各时刻输出与期望，尤其是 Wr=0、R0、读地址变化发生在上升沿之前等情况。

### 13.9 为什么有 Warning

本次完整编译有警告，功能仿真则为 0 警告。两者是不同阶段。已观察到的警告涉及未显式加入的模块源文件、初始顶层名 COExp 残留的 LogicLock 设置、未分配板级引脚、缺少 SDC 约束。

本实验目前验证功能，没有下载到实验板。以后要上板时，必须按实际板卡处理引脚、电气和时钟约束；本指南中的功能仿真成功不能替代这些步骤。

### 13.10 保存对话框中输入文件名没有变化

本次曾遇到窗口失去焦点导致输入没有进入文件名框。处理顺序：点文件名框 → 按 **Alt+N** 聚焦/选择文件名 → 输入完整路径 → 肉眼确认路径已变 → 点保存。

对话框位置可能随窗口移动而改变，照着文字标签操作，不要死记屏幕坐标。有人或自动化正在操作鼠标时，避免另一方同时切换窗口。

### 13.11 功能仿真和时序仿真有什么区别

Functional 用于核对逻辑功能，忽略实现后的传播延迟；Timing 会考虑器件和实现延迟。本实验使用 Functional。

无论哪种仿真，都应根据实际配置的触发沿与延迟解释波形，不能笼统认为“时序仿真就改在下降沿写入”。
